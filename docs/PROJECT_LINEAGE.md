# 야구 시뮬레이션의 계보와 버전 차이

확인일: 2026-11-20 · 대상: `baseball`, `variants/bipedal` · 상태: 로컬 자료와 Git 이력 조사 완료, 통합 저장소 구조 제안

두 폴더는 같은 야구 시뮬레이션 계열의 이전 버전과 후속 재설계다. 2026년 9월 6일 기존 버전을 정리한 직후 새 연구 일지가 만들어졌고, 새 일지는 이전 `baseball`의 문제를 출발점으로 삼았다고 명시한다. **현재 파일이 다르거나 Git 공통 조상이 없다는 이유로 무관한 프로젝트로 분류하면 이 전환을 놓친다.** 하나의 저장소에서 공통 자산과 버전별 실행 코드를 함께 관리할 수 있다.

## 공통 기반과 실제 차이

`baseball` 안에도 여러 개발 단계가 있다. 초기 로봇 팔·차륜형 구성, 보존된 `archive`, 이후 H1과 키프레임 기반 `cognitive_ai`를 모두 포함한다. 기존 폴더 전체를 단순히 고정 베이스 한 종류로 설명하지 않는다. 후속 폴더 역시 처음부터 모든 단계를 자유 베이스로 실행한 것이 아니라, 방향 타격에서 전신·주행·수비로 확장했다.

## 공통 자산과 중복 용량

현재 파일과 과거 Git 객체를 비교하면 H1 STL 메시 21개, 합계 **14,322,164바이트**가 완전히 같다.

- 기존 경로: `baseball/shared_assets/unitree_h1_assets/`
- 후속 경로: `bipedal_baseball/models/unitree_h1_assets/`
- 로컬 모든 Git 참조에서 도달 가능한 blob은 기존 422개, 후속 147개이며, 공유 blob 21개는 전부 이 STL이다. 동일한 Python·MJCF XML blob은 발견하지 못했다.

이 결과는 **바이트 단위 재사용 범위**를 뜻한다. 로직·설계 아이디어까지 무관하다는 뜻은 아니다. 두 버전은 동일한 H1 형상 기반과 과제 계보를 공유하지만, 소스를 그대로 겹쳐 덮어쓸 수 있는 상태는 아니다. STL을 공통화하면 약 14.3MB를 줄일 수 있으며, 폴더 전체 용량의 대부분을 차지하는 가상환경·훈련 결과까지 해결되지는 않는다.

## 동일 저장소에서의 관리 구조

두 버전은 하나의 야구 프로젝트 디렉터리 아래 **동시에 존재하는 변형**으로 배치한다. 아래 이름은 새 관리용 이름이며, 기존 Git 태그나 공식 릴리스명이 아니다.

```text
baseball/
  README.md
  docs/
    lineage.md
    variant_matrix.md
  common/
    assets/unitree_h1/
  variants/
    legacy/                 # f63dc977 기준의 기존 경기 통합 구현
    bipedal/                # ec3f8548 기준의 후속 전신 제어 구현
  evidence/
    manifests/              # 원본 경로, 커밋, 파일 해시, 별도 보관 위치
```

첫 이전에서는 두 소스 트리와 실행 경로를 그대로 들여오고, 원래 커밋 이력도 보존한다. 기존 저장소의 모든 참조와 후속 저장소의 이력을 Git bundle이나 별도 이력 참조로 먼저 남긴다. 코드 경로를 옮길 때 이력을 유지하는 subtree 가져오기를 사용할 수 있으며, 하나의 초기 커밋으로 납작하게 만들지 않는다. 코드만 보관하는 Git bundle에는 미추적·무시된 실험 결과가 포함되지 않으므로 해당 결과는 별도 파일 목록과 압축 보관본에 연결한다.

그다음 STL 21개를 공통 자산으로 옮기고 각 버전 MJCF의 `meshdir` 및 생성기의 경로를 함께 변경한다. 각 버전에서 모델을 로드하고 기존 실행 진입점을 확인한 뒤에 중복 파일을 제거한다. 경로만 삭제하거나 한쪽 폴더를 최신본으로 덮어쓰면 과거 실행과 체크포인트의 출처가 깨진다.

앞으로 결과는 최소한 `variant`, `source_commit`, 모델·정규화 파일 해시, 환경·행동 규약, 평가 시드와 에피소드 수에 연결한다. `Phase 1`, `Phase 7`, `Phase 12`만으로 결과를 식별하지 않는다. 공통화 이후에도 기존 버전과 후속 버전의 결과를 같은 조건에서 얻은 직접 비교로 제시하려면 별도 통제 평가가 필요하다.

## 현재 관리 상태

2026-11-20 조사 기준 기존 버전은 [codemillss/baseball_game](https://github.com/codemillss/baseball_game)의 `main`에 연결돼 있고, 확인한 원격 커밋은 로컬과 같은 `f63dc977`이다. `bipedal_baseball`에는 원격 주소가 없다. 기존 버전의 미추적 `_audit` 기록과 후속 버전에서 Git이 제외한 평가 로그·영상은 기존 커밋에 포함된 것으로 취급하지 않는다.

이 문서는 계보와 통합 기준을 정리한 상태다. 기존 소스·자산 경로, Git 이력, 원본 결과 파일은 변경하지 않았다. 실제 이전 시에는 위 두 기준 커밋과 이후의 미반영 파일을 분리해 기록하고, 새 경로에서 실행 확인을 마친 뒤 관리 기준을 전환한다.


통합 위치: 기존 저장소 `codemillss/baseball_game`. 가져온 후속 버전의 원래 Git commit은 이 통합 커밋의 두 번째 부모로 보존된다. 파일은 `variants/bipedal/` 아래에 있으며 기존 루트 버전과 실행 경로는 유지한다.
